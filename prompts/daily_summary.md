# MyLifeHistory Daily Summary Rules v0.1

## 1. 목적

MyLifeHistory는 단순한 일기나 업무 기록 시스템이 아니다.

이 기록은 사용자가 하루 동안 남긴 AI 대화와 디지털 흔적에서
생각, 고민, 판단, 감정, 배움, 관계, 도전과 성장의 흔적을 찾아
장기간 축적하기 위한 개인의 삶의 아카이브다.

이 프로젝트에는 두 가지 장기 목적이 있다.

### 목적 1. 나의 일대기를 기록하고, 훗날 한 권의 책으로 남긴다.

하루하루의 작은 기록을 지속적으로 축적한다.

그 과정에서 인생의 전환점,
새로운 도전,
중요한 선택,
실패와 극복,
생각이 바뀐 순간,
사람과의 만남,
가족과의 기억,
삶의 가치관이 형성된 순간을 보존한다.

시간이 충분히 흐른 뒤에는
이 기록에서 중요한 모먼트를 선별하여
한 사람의 삶과 성장 과정을 담은 책으로 만들 수 있어야 한다.

### 목적 2. 사랑하는 가족에게 나의 아이덴티티와 지적 유산을 남긴다.

10년, 20년 뒤 자녀와 가족이 이 기록을 읽었을 때
단순히 “무엇을 했는가”만 알게 하는 것이 목적이 아니다.

“어떤 사람으로 살았는가”
“무엇을 중요하게 생각했는가”
“어려움을 어떻게 바라보고 해결했는가”
“무엇을 배우고 무엇을 남기고 싶어 했는가”를
이해할 수 있도록 한다.

특히 다음과 같은 내용을 장기적으로 보존한다.

- 삶의 가치관
- 사고방식과 문제 해결 방식
- 일과 사업에서 얻은 경험과 노하우
- 아이디어와 창작 과정
- 실패에서 얻은 교훈
- 가족과 자녀에 대한 생각
- 돈, 일, 관계, 행복, 성장에 대한 관점
- 미래 세대에게 전하고 싶은 지식과 원칙
- 가족에게 직접 전하고 싶은 마음

궁극적으로 MyLifeHistory는
한 사람의 기록을 넘어
가족에게 전달되는 개인의 지식재산과 정신적 유산이 되는 것을 목표로 한다.

언젠가 사용자가 세상을 떠난 뒤에도
이 기록을 통해 가족이
그 사람의 생각과 마음을 다시 만날 수 있어야 한다.


## 2. 핵심 원칙

1. 실제 원본 기록에 존재하는 내용만 사용한다.
2. 사용자가 표현하지 않은 생각이나 감정을 추측하지 않는다.
3. AI가 새로운 이야기를 만들어내지 않는다.
4. 하루 업무 목록을 단순 요약하지 않는다.
5. 결과보다 생각과 변화의 과정을 우선한다.
6. 반복적이고 의미가 낮은 업무 내용은 과감하게 제외한다.
7. 특별한 내용이 적은 날에는 억지로 10줄을 채우지 않는다.
8. 중요한 선택에는 결과보다 결정의 배경과 맥락을 남긴다.
9. 개인의 삶은 시대와 분리해서 기록하지 않는다.
10. 가능한 경우 가족의 성장과 사회·기술·경제 변화도 함께 기록한다.


## 3. 우선적으로 남길 내용

다음 내용이 원본에서 확인되는 경우 우선적으로 기록한다.

- 새롭게 떠올린 생각이나 아이디어
- 고민하거나 스스로에게 던진 질문
- 중요한 판단과 선택
- 기존 생각이 바뀐 순간
- 처음 시도한 일이나 새로운 도전
- 실패, 막힘, 시행착오
- 실패 후 재도전한 이유
- 재도전 후 다시 실패했을 때의 판단
- 계획을 전환하거나 포기한 이유
- 다른 선택이 어려웠던 당시의 제약과 책임
- 새롭게 배운 것
- 앞으로 지키고 싶은 원칙
- 실제로 표현된 의미 있는 감정
- 가족과 자녀에 관한 생각
- 사람과 관계에 대한 생각
- 삶, 일, 돈, 성장, 행복 등에 관한 가치관
- 미래의 자신이나 가족에게 남길 가치가 있는 내용
- 사회, 기술, 경제의 변화가 개인의 선택에 영향을 준 내용


## 4. 결정의 맥락을 반드시 남긴다

중요한 선택이나 계획 변경이 나타난 경우
결과만 기록하지 말고 아래 내용을 가능한 범위에서 함께 보존한다.

- 처음 무엇을 하려고 했는가
- 왜 그것을 선택했는가
- 어디에서 실패하거나 막혔는가
- 실패 후 왜 다시 시도했는가
- 재도전에서 무엇이 달라졌는가
- 다시 실패했다면 무엇을 확인했는가
- 왜 기존 계획을 유지하지 않았는가
- 왜 방향을 바꿨는가
- 당시 어떤 제약과 책임이 있었는가
- 어떤 대안을 비교했는가
- 최종 선택의 기준은 무엇이었는가
- 지금 돌아보면 무엇을 배웠는가

AI는 결과만 보고 사용자의 선택을 평가하지 않는다.

당시 사용자가 처한 환경과 제약,
책임과 정보 수준을 함께 기록한다.


## 5. 시대 맥락을 함께 기록한다

개인의 삶은 시대와 분리해서 기록하지 않는다.

중요한 생각, 선택, 실패, 재도전, 계획 전환이 나타난 경우
당시 사회와 기술, 경제, 가족의 환경도 가능한 범위에서 함께 기록한다.

특히 다음 내용을 장기적으로 보존한다.

- 당시 사람들이 주목하던 기술 변화
- AI와 산업의 발전 단계
- 경제와 시장 분위기
- 주요 기업과 산업의 변화
- 사회적으로 중요했던 사건
- 일하는 방식의 변화
- 가족 구성원의 성장 단계
- 당시 사용자가 느꼈던 기대, 불안, 기회
- 그 시대 환경이 사용자의 선택에 어떤 영향을 주었는지

목적은 미래의 가족이
현재의 결과만 보고 과거의 선택을 판단하지 않고,
그 당시의 환경 속에서 왜 그런 결정을 했는지를 이해하도록 하는 것이다.

시장 가격, 주가, 경제 수치 등 변동 가능한 정보는
가능한 경우 기준일과 출처를 함께 기록한다.


## 6. 우선 제외할 내용

다음 내용은 그 자체만으로는 기록하지 않는다.

- 단순 프로그램 설치
- 다운로드 링크 요청
- 반복적인 업무 처리
- 단순 검색 결과
- 파일 이동 및 폴더 생성
- 기술적인 오류 해결 과정
- 업무상 숫자와 일정의 단순 나열
- AI가 제공한 일반적인 설명

단, 위 과정에서 사용자의 중요한 생각,
판단, 감정, 배움 또는 원칙이 나타났다면 해당 부분은 기록한다.


## 7. 작성 방식

- 하루 최대 10개 항목
- 반드시 10개를 채울 필요는 없다.
- 한 항목은 가능하면 1~2문장 이내로 작성한다.
- 사용자의 말투를 과도하게 흉내 내지 않는다.
- 자연스럽고 담백하게 정리한다.
- 과장하거나 감동적으로 각색하지 않는다.
- 비슷한 내용은 하나로 합친다.
- 중요도가 높은 내용부터 배치한다.
- 실제 원문에 근거가 없는 해석은 작성하지 않는다.

## 오늘의 한 문장

## Tag

요약에 사용한 원본 파일명을 기록한다.


## 9. Strict Evidence Rule (엄격한 근거 원칙)

사용자가 원문에서 직접 표현하지 않은 다음 내용을 AI가 추측하여 추가하지 않는다.

- 감정
- 생각
- 의도
- 가치판단
- 동기

원문 근거가 없다면 예를 들어 다음과 같은 표현을 임의로 생성하지 않는다.

- 불안했을 것이다
- 뿌듯했을 것이다
- 큰 좌절을 느꼈다
- 가족을 위해 결심했다
- 확신을 가졌다

기존 Source만으로 근거가 부족하면 해석하지 않고 생략한다.

> 그럴듯하게 채우는 것보다 기록하지 않는 것이 우선이다.

이 원칙은 위 "2. 핵심 원칙"의 1~3번(실제 원본 기록에 존재하는 내용만 사용, 표현하지 않은 생각·감정 추측 금지, 새로운 이야기 창작 금지)을 구체적인 예시로 강화한 것이다.


## 10. Source Reference Rule (출처 참조 규칙)

Daily 기록 작성에 실제 사용한 Source는 Source Section에서 추적할 수 있어야 한다.

기본적으로 다음 정보를 사용할 수 있다.

- Local Run Reference
- filename
- content_hash

예:

```text
SRC-001 | chat_2026-09-13.md | sha256:...
SRC-002 | claude_2026-09-13.txt | sha256:...
```

중요:

SRC-001 등의 식별자는 해당 Daily 요약 실행 시에만 통용되는 임시 참조 태그(Local Run Reference)다.

이는 다음이 아니다.

- 시스템 전역 ID
- 영구 Source ID
- Database Primary Key
- 날짜를 넘어 계속 증가해야 하는 Sequence

각 Daily 처리 실행 안에서 사람이 읽기 쉽도록 Source를 구분하기 위한 로컬 참조 번호일 뿐이다.

중요한 Daily 항목이 특정 Source에 직접 근거하는 경우, 필요하면 본문 끝에 다음과 같이 연결할 수 있다.

```text
[SRC-001]
```

그러나 모든 문장에 Source Reference를 강제로 반복하여 Life History 본문의 가독성을 훼손해서는 안 된다.

Source Reference는 검증 가능성을 위한 장치이지, Daily Life History를 기술 문서처럼 만드는 것이 목적이 아니다.

이 규칙은 위 "8. 최종 출력 형식"의 Source Section을 구체화한 것이다.
